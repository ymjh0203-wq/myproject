# 쿠팡 카탈로그 매칭 보조 프로그램 — Phase 0 설계

작성 기준일: 2026-08-10

## 1. 요구사항을 이해한 내용

목표는 상품발굴 프로그램에서 받은 쿠팡 상품 URL 1개를 분석하고, 그 상품과 동일한
카탈로그를 WING에서 찾아 상품등록 입력 화면까지 갈 수 있는지 확인하는 것입니다.
초기 버전은 완전 자동 등록기가 아니라 **사람의 판단을 돕는 반자동 도구**입니다.

Phase 0에서 지켜야 할 선은 다음과 같습니다.

- 상품은 1개만 시험합니다.
- URL에 실제 존재하는 ID만 추출합니다. 없는 값은 추측하지 않습니다.
- 로그인, CAPTCHA, 2차 인증은 사용자가 직접 처리합니다.
- 같은 상품인지 상품명, 이미지, 카테고리, 규격, 옵션 등으로 사람이 확인합니다.
- 등록 입력 화면의 실제 필수 항목을 기록합니다.
- 최종 등록 버튼 직전에서 멈추며 상품을 등록하지 않습니다.
- 이 검증이 성공한 뒤에만 Phase 1을 시작합니다.

## 2. Open API와 WING의 경계

### 공식 Open API로 가능한 범위

- 내 판매자 상품 생성과 승인 요청
- `sellerProductId`로 **내가 등록한 상품** 조회·수정
- 승인된 옵션의 `vendorItemId`로 가격, 재고, 판매상태 조회·변경
- 카테고리 추천, 카테고리 목록·메타정보 조회
- 출고지·반품지 등 상품등록에 필요한 코드 조회
- 상품을 만들 때 이미지, 상세설명, 배송, 고시, 옵션 등의 데이터 전달

상품 생성 API의 `requested=false`는 승인 요청 없이 내용을 저장할 수 있지만, 실제
판매자 상품 레코드는 생성합니다. Phase 0의 “실제 등록 없음” 조건과 혼동될 수 있어
이번 코드에서는 상품 생성 API를 전혀 호출하지 않습니다.

### Open API로 불가능하고 WING에서 해야 하는 범위

쿠팡 공식 FAQ는 상품구성, **카탈로그 매칭관리**, 자동가격조정 기능을 Open API가
지원하지 않으며 WING에서 사용하라고 명시합니다. 따라서 다음은 WING 전용으로
분류합니다.

- 상품 등록 화면의 `카탈로그 매칭하기`에서 기존 카탈로그 검색과 후보 확인
- 위너/카탈로그 매칭 대상 선택
- 이미 등록·승인된 내 상품을 대상으로 하는 별도 `카탈로그 매칭관리` 화면의 작업
- 현재 WING 등록폼으로 이동해 실제 필수 항목 확인

2026-08-10 실제 화면 확인에서 두 경로가 분리되어 있음을 확인했습니다. 신규 상품을 기존
카탈로그에 붙여 등록하는 PoC는 **상품관리 > 상품 등록 > 카탈로그 매칭하기**를 사용합니다.
별도 **카탈로그 매칭관리**는 승인완료된 등록상품의 사후 매칭 요청용입니다.

### 공개 상품 URL만으로 할 수 없는 것

- 다른 판매자의 상품을 판매자 Open API의 `sellerProductId` 조회로 가져오기
- URL에 없는 카탈로그 ID, 브랜드, 카테고리, 옵션을 임의 생성
- WING 검색 결과를 보지 않고 어떤 ID가 검색키인지 확정

### 공식 ID 의미

| ID | 공식적으로 확인된 의미 | Phase 0 처리 |
|---|---|---|
| `sellerProductId` | 상품 생성 후 받는 등록상품 ID. 내 상품 묶음 관리 단위 | 일반 소비자 상품 URL에서는 추출하지 않음 |
| `productId` | 노출상품 ID. 하위에 item/vendor item이 있고 결합·분리로 변경될 수 있음 | `/vp/products/{값}` 또는 명시적 쿼리에서만 추출, 실제 WING 검색 성공을 확인한 첫 후보 |
| `vendorItemId` | 변경되지 않는 가장 작은 옵션 단위 | 명시적 쿼리에서만 추출, 미확인 대체 후보 |
| `itemId` | 상품 조회 응답의 옵션 항목에 함께 나타남. 공식 ID FAQ에는 별도 정의 없음 | 명시적 쿼리에서만 추출, 의미를 확대 해석하지 않음 |
| 카탈로그 관련 ID | 표준 소비자 URL과 공개 FAQ만으로 확정 불가 | URL에 관련 이름의 값이 실제 있으면 ‘미확인’으로만 기록 |

## 3. 단계별 권장 자동화 수준

| 작업 | 권장 방식 | 이유 |
|---|---|---|
| URL 검증·ID 추출 | 자동 | 문자열 분석이라 계정·정책 위험이 낮음 |
| 검색값 준비·복사 | 자동 | 브라우저 조작 없이 반복 작업을 줄임 |
| WING 열기 | 반자동 | 사용자의 기존 로그인과 정상 브라우저를 사용 |
| 로그인·2차 인증·CAPTCHA | 수동 | 보안 절차를 우회하지 않음 |
| 카탈로그 검색 | Phase 0은 수동 | 실제 지원 검색키와 화면 구조를 먼저 확인해야 함 |
| 후보 비교 | 반자동 설계, Phase 0은 수동 기록 | 잘못된 카탈로그 선택의 피해가 큼 |
| 카탈로그 선택 | 수동 | 최종 동일성 판단은 사용자 책임으로 유지 |
| 등록정보 준비 | 추후 반자동 | 실제 필수 필드를 Phase 0에서 확인한 뒤 구현 |
| 최종 등록 | 수동 | 초기 버전의 안전 경계 |

결론: 제안된 “WING 열기 → 검색값 준비 → 사용자 선택 → 등록정보 준비 → 사용자 최종
등록” 구조가 완전 자동보다 안정적이며 우선 권장 방식입니다.

## 4. 가장 큰 기술 위험

1. **공식 카탈로그 검색 API 부재 — 매우 높음**  
   WING UI에 의존해야 합니다. 화면이나 정책이 바뀌면 자동화가 깨질 수 있습니다.

2. **잘못된 카탈로그 매칭 — 매우 높음**  
   이름이 비슷해도 모델, 수량, 색상, 사이즈가 다를 수 있습니다. Phase 0에서는 자동
   선택을 금지하고 사람이 이미지·규격·옵션을 모두 확인합니다.

3. **검색키 불확실성 — 중간**  
   실제 상품 1건에서 `productId` 검색 성공을 확인했고 검색창은 상품 URL도 지원한다고
   안내합니다. `vendorItemId`와 `itemId` 지원 여부는 아직 확인되지 않았으므로 대체 후보
   순서를 “지원 확정”으로 해석하면 안 됩니다.

4. **로그인·보안·자동화 차단 — 높음**  
   세션 저장, CAPTCHA/2차 인증 우회는 구현하지 않습니다. 이 때문에 완전 무인 실행은
   목표에서 제외합니다.

5. **WING 등록필드 변경 — 높음**  
   카테고리, 브랜드, 고시, 해외구매대행 여부에 따라 필수 항목이 달라집니다. 2026년에는
   브랜드 ID와 상품 식별 코드 관련 변경도 공지되어 있으므로 현재 화면의 필드를 직접
   기록해야 합니다.

6. **ID 수명 차이 — 중간**  
   `productId`는 결합·분리로 바뀔 수 있습니다. 원본 URL과 추출 시각, 다른 ID를 함께
   보관해야 합니다.

7. **브라우저 자동화 유지보수 — 중간~높음**  
   Playwright 자동 입력은 Phase 0의 수동 흐름이 성공하고 WING 정책 확인 후에만 검토합니다.

## 5. Phase 0 실행 설계

1. 프로그램에 실제 시험 상품 URL 1개를 붙여넣습니다.
2. 도메인과 URL 형식을 검증합니다.
3. URL 경로·쿼리에 실제 있는 `productId`, `vendorItemId`, `itemId`만 보여줍니다.
4. `productId`를 첫 검색값으로 사용하고, 필요하면 상품 URL·`vendorItemId`·`itemId`를
   대체 후보로 한 번씩 시험합니다.
5. **WING 열기**를 누르고 사용자가 직접 로그인·인증합니다.
6. 사용자가 **상품관리 > 상품 등록**의 `카탈로그 매칭하기` 영역으로 이동합니다.
7. 각 검색값의 결과 유무를 확인하고 성공한 값 종류를 기록합니다.
8. 후보를 상품명, 대표 이미지, 카테고리, 모델/규격, 옵션, 구성 수량, 색상, 사이즈,
   핵심 속성으로 비교합니다.
9. 사용자가 같은 상품을 직접 선택하고 등록 입력 화면으로 이동합니다.
10. 화면에 실제 표시된 필수 입력 항목을 메모한 뒤 최종 등록 직전에서 멈춥니다.
11. “실제 상품을 등록하지 않았음”을 확인하고 JSON 보고서를 저장합니다.

이 PoC는 네트워크 요청을 반복하거나 WING 내부 API를 조사하지 않습니다.

## 6. 파일 구조

```text
catalog_match_poc/
├─ main.py                         # 실행 진입점
├─ 설치.bat                        # 처음 한 번 실행
├─ 실행.bat                        # 프로그램 실행
├─ 테스트.bat                      # 로컬 자동 테스트
├─ requirements.txt
├─ README.md
├─ poc/
│  ├─ url_parser.py                # URL 검증·ID 추출
│  ├─ report_store.py              # 민감정보 제거·결과 저장
│  └─ ui.py                        # 최소 PySide6 화면
├─ tests/
│  ├─ test_url_parser.py
│  └─ test_report_store.py
├─ docs/
│  └─ Phase0_설계_및_판정기준.md
└─ data/
   └─ reports/                     # 실행 후 생김, Git에 저장하지 않음
```

Phase 1에서는 `data/app.db` SQLite, 상태 저장소, 상품 목록 UI를 이 폴더에 추가하는
방식을 권장합니다. Phase 0에서는 제품 1개 결과만 저장하므로 JSON이 더 단순하고 검토하기
쉽습니다.

## 7. 최소 UI

- 쿠팡 URL 입력과 **URL 분석** 버튼
- ID 종류, 값, URL 위치, 공식 의미 표
- WING 주소 입력(선택 사항)과 **WING 열기** 버튼
- 시험할 ID 또는 상품 URL 선택과 **검색값 복사** 버튼
- 사람이 확인해야 하는 8개 체크박스
- 검색 성공값, 카탈로그 조회수·별점·배송정보, 카탈로그 비교, 실제 등록필드, 실패 지점 메모
- 검증 결과 JSON 저장
- 실제 등록 버튼은 없음

WING은 Windows 기본 브라우저가 아니라 설치된 Google Chrome 실행 파일을 직접 찾아
엽니다. 별도 자동화 프로필을 만들지 않으므로 평소 Chrome의 로그인 상태를 재사용합니다.

## 8. Python 라이브러리

### 지금 필요한 것

- Python 3.10 이상(3.12 권장)
- PySide6: Windows 데스크톱 화면
- 표준 라이브러리 `urllib.parse`: URL 분석
- 표준 라이브러리 `json`, `pathlib`, `tempfile`: 안전한 결과 저장
- 표준 라이브러리 `webbrowser`: 사용자의 기본 브라우저로 WING 열기
- 표준 라이브러리 `unittest`: 테스트

### 지금 넣지 않는 것

- `requests`: Phase 0은 공개 페이지 크롤링이나 Open API 호출을 하지 않음
- `playwright`: 수동 PoC 성공과 정책 확인 전에는 브라우저 DOM 자동화를 하지 않음
- SQLite: 상품 1개 검증에는 불필요하며 Phase 1에서 추가

## 9. 사용자가 준비해야 할 정보

- 실제로 매칭할 쿠팡 상품 URL 1개(가능하면 `vendorItemId`와 `itemId`가 포함된 전체 URL)
- 해당 상품이 같은지 판단할 수 있는 브랜드, 모델명, 규격, 구성수량, 옵션 자료
- 정상 사용 가능한 WING 판매자 계정과 상품 등록 메뉴 접근 권한
- 사용자 본인이 직접 처리할 로그인·2차 인증 수단
- WING 상품 등록 주소(기본값은 프로그램에 포함됨)
- 시험 중 보이는 후보 개수와 검색 성공 ID 종류
- 선택 후 등록 화면에 실제 보이는 필수 항목 목록
- 상품을 실제 등록하지 않고 중단할 수 있는 시간과 확인 절차

Open API 키, 비밀번호, 쿠키, 인증토큰은 Phase 0에 필요하지 않으며 제공하면 안 됩니다.

## 10. 성공·실패 판정 기준

### 코드 기술검증 성공

- 정상 쿠팡 URL에서 경로의 `productId`와 쿼리의 ID를 정확히 추출
- 없는 ID를 생성하지 않음
- 다른 도메인과 모순되는 ID를 경고
- 민감정보 형태가 보고서에 들어오면 삭제
- 단위 테스트가 모두 통과

### 실제 업무 흐름 성공

아래가 모두 충족되어야 합니다.

- 유효한 ID를 하나 이상 추출함
- WING 상품 등록의 `카탈로그 매칭하기` 화면에 정상 접근함
- 추출 ID 중 적어도 하나가 실제 검색에 사용됨
- 원하는 카탈로그 후보를 찾음
- 상품명·이미지·카테고리·규격·옵션 비교로 같은 상품임을 확인함
- 사용자가 카탈로그를 직접 선택함
- 등록 입력 화면에 도달함
- 현재 필수 입력 항목을 기록함
- 최종 등록 직전에서 중단함
- 실제 상품이 생성·등록되지 않음

### 실패 또는 차단

- 어떤 추출 ID로도 후보가 검색되지 않음
- 올바른 카탈로그가 존재하지 않거나 구별할 수 없음
- 계정 권한으로 상품 등록의 카탈로그 매칭 영역에 접근할 수 없음
- 정상적인 사용자 인증 후에도 CAPTCHA/보안정책으로 업무를 진행할 수 없음
- 상품 선택 뒤 등록 화면으로 이동할 수 없음
- 최종 등록과 분리된 안전한 중단 지점을 확보할 수 없음

실패 시 내부 API 역공학, 토큰 탈취, CAPTCHA 우회, 프록시·계정 회전은 대안이 아닙니다.
검색어 복사와 수동 선택 중심의 흐름을 유지하거나, 쿠팡 WING 문의를 통해 지원 범위를
확인합니다.
